## 二、我们反对的不是收费，是这种收法

做软件有成本，收费天经地义 —— 服务器、签名、更新通道都要钱。开源项目商业化有一条成熟且体面的路：**社区版与商业版并存（Open Core）**。

| | 社区版 | 商业版 |
|---|---|---|
| 代码 | 继续 MIT 开源，仓库可查 | 可闭源 |
| 价格 | 永久免费 | 按需付费 |
| 功能 | 核心功能完整可用 | 多设备、云同步、优先支持、定制 |
| 用户选择 | 不想花钱就用社区版，功能够用 | 愿意花钱买便利 |

这样做的项目很多，社区不但不骂，还会帮着提 issue。因为它把「免费」当承诺，把「付费」当增值，两条线互不干扰。

这次是反过来的：

1. 代码以 MIT 发布，README 与脚本里反复写「完全免费开源」「花钱买到请立即申请退款」；
2. 然后删掉源码（`d00b305`），成品加群号登录 + 一机一码激活；
3. 再把「换机解绑」定价 3 元/次、「多设备同时用」定价 10 元/周、25 元/月。

这三项卖的不是新增的增值服务，而是**原本在本地就能做到的事** —— 同一个脚本拷到另一台电脑。把它人为锁住再单收费，用户就只剩两条路：付钱，或者退回旧版。本仓库提供第三条：自己维护一份。

更关键的是，MIT 已经授权出去的版本**收不回来**。与其「撤源码 + 上锁」，不如老实做双版本：前者消耗的是信任，后者才是生意。

需要 Python 3.8+，无第三方依赖。

```bash
python src/破甲一键通.py                     # 交互菜单
python src/破甲一键通.py --status            # 只读：所有目标查一遍
python src/破甲一键通.py --diagnose          # 只读：详细取证
python src/破甲一键通.py --dry-run --apply   # 预演，不改盘
```

## 五、纯净版到底改了什么

**只删不加。** 被移除的 16 个顶层函数，全部属于加密封条/反篡改链：

| 函数 | 作用 |
|---|---|
| `_k0` `_k1` `_k2` | 密钥派生 |
| `_d0` `_d1` `_d2` `_st` | 解密与派生 |
| `_seal_decode` | 解出加密载荷 `_SEALED` |
| `_seal_read_source` | 读回自身源码参与校验 |
| `_seal_source_problem` `_seal_assert_source` `_seal_verify_source` | 源码完整性校验，失败即自毁/告警 |
| `_seal_alarm` | 篡改告警 |
| `_integrity_digest` `verify_integrity` | 运行时完整性摘要 |
| `_say_agent_reminder` | 往对话里塞提醒（依赖封条） |

`_SEALED` 从「加密后由 `_seal_decode` 解出」变回一份**明文常量表**，其余行为逻辑一行没动：备份/还原、升级自愈、幂等、护照、15 个目标、全部命令行开关、`--status` 输出格式全部照旧。

副作用说明白：**原来那层「改了源码就报警/自毁」的保护没有了**。这正是 Fork 需要的结果，但也意味着你拿到的是可随意修改的普通脚本 —— 请自行校验哈希，别用来路不明的副本。
